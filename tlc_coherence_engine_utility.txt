One important correction for the next revision

For a true production TileLink-C implementation, I would change the above architecture before integrating it with the previously generated modules:

Do not use dir_owner directly as a sink ID. A directory owner/client ID and a TL-C sink ID are different namespaces.
tlc_sink_table.sv should allocate the actual sink ID for each Probe/Grant transaction.
tlc_probe_tracker.sv should track multiple simultaneous probes, rather than the single probe_outstanding_q shown here.
tlc_coherence_engine.sv should maintain a transaction context per source, rather than one global active_* context, if MAX_OUTSTANDING > 1.
AcquireBlock/AcquirePerm should be decoded using the exact TileLink parameter encodings from tlc_pkg.sv; they should not be inferred merely from is_block/is_perm.
Directory updates need to be atomic with transaction completion, otherwise a stalled Grant can leave the directory in an inconsistent state.
The final implementation should have separate FSMs for Acquire, Probe, Release and Grant, coordinated by a transaction scoreboard, rather than one monolithic FSM.

That is the direction I recommend for the next tlc_top.sv: a multi-outstanding, source-indexed coherence controller rather than the single-active-transaction controller above.
